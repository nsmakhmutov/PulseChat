# Анонимный шёпот — changelog

Версия: **1.0.61**. Фича: опция «Анонимно» для шёпота одному собеседнику.

## Что делает

При включённой галочке «👤 Анонимно»:
- **Получатель** видит в баннере и системном оверлее «🤫 Аноним шепчет вам…»
  вместо реального ника отправителя.
- В UDP-заголовке пакета, который доходит до получателя, **физически нет**
  реального `sender_uid` — сервер переписывает его на `ANONYMOUS_UID` перед
  ретрансляцией. Проверено в e2e-симуляции (`SENDER_UID.to_bytes` отсутствует
  в байтах header'а у получателя).

## Что это НЕ делает

- **Хост встроенного сервера** по-прежнему видит реального отправителя —
  ему нужен `sender_uid` для роутинга, keepalive `udp_map` и защиты от спуфа.
  Это архитектурное ограничение client-server модели, не баг.
- Трафик-анализ: если получатель знает, кто сейчас онлайн и в каком канале,
  он может по времени корреляции угадать анонима. Защита требует dummy-трафика
  и выходит за рамки этой фичи.

## Протокол

Новый флаг в 1-байтовом поле `flags` UDP-заголовка:
```
FLAG_ANONYMOUS = 128   # 0x80 — ставится вместе с FLAG_WHISPER
```

Зарезервированный маркер вне диапазона реальных uid (которые
`secrets.randbelow(10**9)+1`):
```
ANONYMOUS_UID = 0xFFFFFFFE   # 4 294 967 294
```

Поток пакета:

```
[sender]  header(my_uid, ts, seq, FLAG_WHISPER|FLAG_ANONYMOUS) + target_uid(4) + opus
   ↓
[server]  видит FLAG_ANONYMOUS → переписывает header на
          (ANONYMOUS_UID, ts, seq, flags), ретранслирует target_addr.
          Реальный my_uid остаётся в своём udp_map — только для keepalive.
   ↓
[recv]    видит uid == ANONYMOUS_UID → is_anonymous_uid() → UI показывает «Аноним».
```

## UX

**Правый клик по собеседнику → UserOverlayPanel:**
```
┌─ 🔊 Громкость  [====]  100% ─┐
│ ─────────────────────────────│
│ 🔇  Заглушить                │
│ 🤫  Шепнуть  (удерживай)     │
│ ☐ 👤 Анонимно (получатель...)│  ← новое
│ Остальные тебя не слышат...  │
│ ⚡ Буст звука                 │
│ 👟 Пнуть (держи 3с)           │
│ 📁 Передать файл              │
└───────────────────────────────┘
```

Галочка запоминается персонально для каждого собеседника по uid (ключ
`whisper_anonymous_{uid}` в `QSettings`). Переключение галочки **во время
активного удержания** PTT — меняет режим «на лету» без отпускания кнопки
(см. `_on_anonymous_toggled`).

**Настройки → Персонализация → Горячие клавиши:**
В ряду функции «🤫 Шёпот → {ник}» появляется компактная галочка «👤» перед
кнопкой удаления. Видима только если в выпадайке выбрана функция шёпота;
при смене на другую функцию автоматически сбрасывается (чтобы не утекало
в `whisper_slot_{i}_anon`).

## Протестировано

E2E-симуляция протокола в `/home/claude/work` (sender → server → receiver):
```
[plain]  receiver sees uid=12345 flags=64
[anon]   receiver sees uid=0xfffffffe flags=192
[wire]   sender_uid 00003039 NOT present in anon header
```

## Бэк-совместимость

- Старые клиенты **без** патча, получая пакет с `FLAG_ANONYMOUS` (flags=192):
  `flags & FLAG_WHISPER == True` — пакет распакуется штатно, только с uid =
  `0xFFFFFFFE`. В `known_uids` такого нет → UI покажет «Кто-то» вместо
  «Аноним». Звук играет, функциональность не ломается.
- Старые клиенты **без** патча, отправляющие: просто не умеют ставить флаг,
  работает как раньше.
- Старый сервер с новыми клиентами: новый флаг сервер проигнорирует, пакет
  уйдёт с реальным `sender_uid` — анонимности не будет, но всё работает.
  Для полной анонимности сервер тоже должен быть обновлён.

## Что можно улучшить (вне скоупа)

1. **Эфемерные pseudo-uid**: вместо одного `ANONYMOUS_UID` сервер мог бы
   генерировать per-session случайный uid в диапазоне `[0xFFFF0001, 0xFFFFFFFD]`,
   чтобы два одновременных анонима имели разные `RemoteUser`/jitter-buffer и
   их аудио не смешивалось.
2. **Dummy-трафик**: отправлять анонимные whisper-пакеты с тишиной от случайных
   пользователей, чтобы защитить от трафик-анализа.
3. **Индикация в оверлее у шептуна**: визуально показывать отправителю, что
   текущий режим — анонимный (сейчас только через текст кнопки «🤫 Шепчу анонимно»).
